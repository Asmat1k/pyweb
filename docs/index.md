# WebTransport и WebSocket

**Выбор технологий WebTransport и WebSocket для двунаправленной передачи данных в веб-приложениях.**

Исследование посвящено выбору транспорта для чатов, совместного редактирования,
телеметрии и интерактивных приложений. Сравнение строится вокруг четырёх критериев:
скорости подключения, задержки сообщения, накладных расходов и поведения при потерях пакетов.

Сайт подготовлен в рамках задания 1 «Генераторы статических сайтов для публикации
результатов исследований». Материалы написаны в Markdown и собираются Python-генератором
MkDocs с темой Material.

## Критерии выбора

| Критерий | Исследовательский вопрос | Что фиксировать |
|---|---|---|
| Время установки соединения | Как быстро приложение может начать обмен? | Время до готовности, мс; отношение к базовому RTT |
| Задержка доставки сообщения | Как долго сообщение идёт до получателя и обратно? | RTT сообщения, медиана, p95, p99; односторонняя задержка при синхронизации часов |
| Накладные расходы | Сколько ресурсов требуется сверх полезных данных? | Служебные байты, повторные передачи; отдельно CPU и память |
| Поведение при потерях пакетов | Как потери влияют на свежесть и полноту данных? | Недоставленные и опоздавшие сообщения, хвост задержек |

!!! note "Время подключения и RTT — разные величины"
    Подключение может включать несколько сетевых обменов. RTT — время пути
    запроса и ответа. В методике эти показатели учитываются раздельно.

## Сравниваемые режимы

| Режим | Модель данных | Доставка |
|---|---|---|
| WebSocket поверх TLS/TCP | Двунаправленный обмен сообщениями | Надёжная, упорядоченная в пределах соединения |
| WebTransport: streams поверх HTTP/3 | Один или несколько двунаправленных потоков байтов | Надёжная, упорядоченная внутри потока |
| WebTransport: datagrams поверх HTTP/3 | Отдельные сообщения | Без гарантии доставки и порядка |

Область сравнения ограничена WebSocket поверх TCP и WebTransport поверх
HTTP/3. Другие отображения протоколов рассматриваются в [ограничениях](limitations.md).
